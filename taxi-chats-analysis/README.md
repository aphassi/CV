# Анализ сообщений из чатов таксистов

Командный проект по созданию системы для сбора, хранения и анализа сообщений из сообществ водителей такси.

Основная цель проекта — преобразовать неструктурированные сообщения из чатов таксистов в данные, пригодные для поиска и аналитики. Система позволяет находить повторяющиеся сообщения, выявлять похожий контент и выполнять семантический поиск.

Проект может использоваться для анализа обсуждений водителей, поиска повторяющихся проблем сервиса, выявления потенциально подозрительных паттернов и получения данных для дальнейшего продуктового анализа.

Данный репозиторий содержит модуль, разработанный мной в рамках более крупного командного проекта.

## Моя часть проекта

Я отвечала за модуль поиска дублей и похожих сообщений.

Были реализованы:

- нормализация и очистка текста
- поиск точных дублей сообщений
- поиск почти дублей по коэффициенту текстового сходства
- получение эмбеддингов сообщений
- хранение эмбеддингов в PostgreSQL с использованием `pgvector`
- подготовка структуры таблиц для хранения результатов
- подготовка данных для дальнейшего анализа и визуализации в Superset

## Архитектура модуля

Модуль работает как часть общего DWH-пайплайна проекта.

Python-flow получает подготовленные сообщения из PostgreSQL, выполняет обработку и записывает результаты обратно в CDM-слой базы данных.

Результаты затем могут использоваться для SQL-аналитики и визуализации в Superset.

## Поиск точных дублей

Перед сравнением сообщений выполняется нормализация текста:

После нормализации для текста вычисляется хэш.

Сообщения с одинаковым нормализованным текстом объединяются в группы точных дублей.

Отдельно сохраняются сообщения, входящие в каждую группу дублей.

## Поиск почти дублей

Для сообщений, не попавших в группы точных дублей, выполняется поиск похожих сообщений.

Сравнение производится с помощью `SequenceMatcher`.

Дополнительно используется ограничение на разницу длины сообщений, чтобы уменьшить количество лишних сравнений.

Пара сообщений считается почти дублем, если коэффициент сходства превышает заданный порог.

## Семантический поиск

Для семантического сравнения сообщений используются текстовые эмбеддинги.

Для каждого сообщения:

1. Получается векторное представление текста через API модели эмбеддингов
2. Эмбеддинг сохраняется вместе с исходным сообщением в PostgreSQL
3. Для хранения векторов используется расширение `pgvector`
4. Для ускорения поиска похожих сообщений используется HNSW-индекс с cosine similarity

Это позволяет находить сообщения, близкие по смыслу, даже если они написаны разными словами.

## Структура данных

В рамках модуля используются следующие таблицы:

### `duplicate_exact_groups`

Хранит агрегированную информацию о группах точных дублей:

- текст
- его хэш
- количество повторений
- время первого и последнего появления

### `duplicate_exact_items`

Хранит конкретные сообщения, входящие в группы точных дублей.

### `duplicate_near_pairs`

Хранит пары почти одинаковых сообщений и рассчитанный для них коэффициент сходства.

### `message_embeddings`

Хранит сообщения и соответствующие им векторные представления для семантического поиска.

Для поля с эмбеддингами используется тип `VECTOR(256)`
